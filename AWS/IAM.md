# 👤 Introduction to IAM Services in AWS

---

## 🔹 What is IAM?
- **IAM (Identity and Access Management)** is a web service in AWS that helps you securely control:  
  - **Who** can access AWS resources (Identity).  
  - **What** actions they can perform (Access).  
- It is **global** (not region-specific).  

---

## 🔹 Key Features of IAM
1. **Users** – Individual accounts for people or applications.  
2. **Groups** – Collection of users with common permissions.  
3. **Roles** – Temporary access permissions for AWS services or users.  
4. **Policies** – JSON documents defining permissions.  
5. **MFA (Multi-Factor Authentication)** – Extra layer of security.  
6. **Granular Permissions** – Control access at resource and action level.  

---

## 📊 IAM Components Overview

| Component   | Description |
|-------------|-------------|
| **User**    | Represents an individual with credentials (username + password + access keys). |
| **Group**   | A collection of users with shared permissions. |
| **Role**    | Provides temporary permissions to AWS services or users without credentials. |
| **Policy**  | JSON document that defines "Allow" or "Deny" permissions. |

---

## ✅ Benefits of IAM
- **Centralized control** of AWS accounts.  
- Provides **granular permissions** (least privilege).  
- Supports **temporary security credentials**.  
- Increases **security with MFA**.  
- No extra cost (free service).  

---

## 🎯 Summary
- IAM = Securely **manage access** to AWS resources.  
- Key elements → **Users, Groups, Roles, Policies**.  
- Ensures the **principle of least privilege** for security best practices.

# Creating IAM Users in AWS

## 1. Log in to AWS Management Console
- Go to [AWS Console](https://aws.amazon.com/console/).
- Sign in with your **root account** or an IAM user with **AdministratorAccess**.

---

## 2. Navigate to IAM
- In the **search bar**, type **IAM**.
- Click on **IAM (Identity and Access Management)**.

---

## 3. Create a New User
1. On the left panel, click **Users** → **Add users**.
2. Enter a **User name** (e.g., `devops_user`).
3. Select **Access type**:
   - **Programmatic access** → for **API/CLI/SDK access**.
   - **AWS Management Console access** → for **console login**.
   - You can select both if required.

---

## 4. Set Permissions
Choose one of the following:

### Option A: Attach existing policies directly
- Select policies like **AdministratorAccess** or specific ones like **S3FullAccess**, **EC2FullAccess**.

### Option B: Add user to group
- Create a group with predefined policies.
- Add the user to that group for easier management.

### Option C: Copy permissions from existing user
- Useful if you want the new user to have the same permissions as an existing user.

### Option D: Attach custom policy
- Write a **JSON policy** with fine-grained permissions.

---

## 5. Optional: Set Tags
- Add **key-value tags** like:
  - `Department = DevOps`
  - `Project = CloudTraining`
- Tags help in **tracking and auditing**.

---

## 6. Review and Create User
- Verify **username, access type, and permissions**.
- Click **Create user**.

---

## 7. Save Credentials
- After creation, AWS will show:
  - **Access key ID & Secret access key** (for CLI/SDK)
  - **Console login URL** (for console access)
- **Important:** Download `.csv` file or copy credentials. **Secret key won’t be shown again**.

---

## 8. Best Practices
- Enable **MFA (Multi-Factor Authentication)** for console users.
- Assign **least privilege**: only grant necessary permissions.
- Rotate access keys regularly.
- Use **groups** instead of individual user policies for easier management.

# Assigning Console and Programmatic Access for IAM Users

## 1. Log in to AWS Management Console
- Go to [AWS Console](https://aws.amazon.com/console/).
- Sign in with a **root account** or IAM user with **AdministratorAccess**.

---

## 2. Navigate to IAM
- In the **search bar**, type **IAM**.
- Click **IAM (Identity and Access Management)**.

---

## 3. Add or Select a User
1. On the left panel, click **Users**.
2. Either **select an existing user** or click **Add users**.

---

## 4. Assign Access Type

### **Programmatic Access**
- Check **Programmatic access**.
- Provides an **Access Key ID** and **Secret Access Key**.
- Used for:
  - AWS CLI
  - AWS SDKs
  - API calls

### **AWS Management Console Access**
- Check **AWS Management Console access**.
- Set a **console password**:
  - **Autogenerated password** (recommended) or
  - **Custom password**
- Options:
  - Require user to **reset password on first login** (recommended).

### **Both Access Types**
- You can select both if the user needs **CLI/API access** and **console login**.

---

## 5. Set Permissions
- Attach **existing policies**, **add to a group**, **copy from another user**, or **attach a custom policy**.

---

## 6. Review and Create User
- Confirm **username, access type, and permissions**.
- Click **Create user**.

---

## 7. Save Credentials
- For **programmatic access**:
  - Copy **Access Key ID** and **Secret Access Key**.
  - Download `.csv` file.
- For **console access**:
  - Share the **console login URL** with the user.

---

## 8. Best Practices
- Enable **MFA** for console users.
- Assign **least privilege** policies.
- Rotate access keys regularly.
- Use **groups** for easier permission management.

# IAM Group Creation and Policy Attachment

## 1. Log in to AWS Management Console
- Go to [AWS Console](https://aws.amazon.com/console/).
- Sign in with a **root account** or IAM user with **AdministratorAccess**.

---

## 2. Navigate to IAM
- In the **search bar**, type **IAM**.
- Click **IAM (Identity and Access Management)**.

---

## 3. Create a New Group
1. On the left panel, click **User groups** → **Create group**.
2. Enter a **Group name** (e.g., `DevOpsTeam`).

---

## 4. Attach Policies to the Group
- AWS will show a list of **policies**.
- Choose one or multiple policies:
  - **AdministratorAccess** → Full access
  - **AmazonS3FullAccess** → S3-specific access
  - **AmazonEC2FullAccess** → EC2-specific access
- You can also:
  - **Create custom policy** in JSON format for fine-grained permissions.

---

## 5. Review and Create Group
- Verify the **group name** and **policies attached**.
- Click **Create group**.

---

## 6. Add Users to the Group
1. Select the group → **Add users**.
2. Choose one or multiple IAM users to add.
3. Click **Add users**.

---

## 7. Best Practices
- Use **groups** instead of attaching policies to individual users.
- Assign **least privilege** policies.
- Rotate access keys regularly for programmatic users.
- Enable **MFA** for console users in the group.

# Practical Demo: IAM Policy Implementation and Restriction Tests

## 1. Objective
- Learn how to **attach policies to users or groups**.
- Test **permissions and restrictions**.
- Verify **least privilege** principle.

---

## 2. Prerequisites
- IAM user with **AdministratorAccess**.
- Existing **IAM users** or **groups**.
- AWS Management Console access.

---

## 3. Steps for Policy Implementation

### Step 1: Create a Custom Policy
1. Navigate to **IAM → Policies → Create policy**.
2. Select **JSON** tab.
3. Example: Allow **S3 read-only access**:

```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "s3:GetObject",
                "s3:ListBucket"
            ],
            "Resource": [
                "arn:aws:s3:::example-bucket",
                "arn:aws:s3:::example-bucket/*"
            ]
        }
    ]
}
```

## Step 2: Attach Policy to User or Group
- Navigate to **Users** or **Groups**.  
- Select the target **user/group** → **Add permissions** → **Attach policies**.  
- Choose the custom policy (e.g., `S3ReadOnlyPolicy`) → **Add permissions**.

---

## Step 3: Test Permissions
- Log in as the **user**.  
- Try actions **allowed by policy**:
  - List S3 buckets.  
  - Read objects from the allowed bucket.  
- Try actions **not allowed**:
  - Upload a file to S3 → should **fail**.  
  - Delete objects → should **fail**.

---

## Step 4: Modify Policy for Restrictions
- Update policy to **add or remove actions**.  
- Test user access again.  
- Observe how **restrictions are enforced immediately**.

---

## 4. Best Practices for Policy Testing
- Use a **separate test user** to avoid impacting production.  
- Always start with **least privilege**.  
- Combine **AWS managed policies** with **custom policies** for flexibility.  
- Enable **CloudTrail** to monitor access attempts and failures.

---

## 5. Learning Outcome
- Understand how **IAM policies control access**.  
- Learn to **test and verify restrictions**.  
- Practice **secure permission management**.

# IAM Roles in AWS

## 1. What is an IAM Role?
- An **IAM Role** is an AWS identity with **specific permissions** that can be assumed by:
  - IAM users
  - AWS services
  - Applications or external identities
- Unlike IAM users, roles **do not have long-term credentials**.
- Roles provide **temporary security credentials** for secure access.

---

## 2. Importance of IAM Roles
- **Secure access** without sharing long-term credentials.
- **Cross-account access** between AWS accounts.
- Allow **AWS services to interact** with each other securely.
- **Temporary access** reduces risk of credential leakage.
- Centralized **permission management**.

---

## 3. Types of IAM Roles

| Role Type                     | Description                                                                 |
|--------------------------------|-----------------------------------------------------------------------------|
| **Service Role**               | Assigned to an AWS service to perform actions on your behalf (e.g., EC2, Lambda). |
| **Cross-Account Role**         | Allows users from another AWS account to access your resources.           |
| **AWS Service-Linked Role**    | Predefined roles linked to specific AWS services for automation.           |
| **Web Identity Federation Role** | Allows users from external identity providers (like Google, Facebook, Cognito) to access AWS resources. |
| **EC2 Instance Role**          | Provides temporary credentials to applications running on EC2 instances.  |

---

## 4. Practical Demo: Creating and Using a Role

### Step 1: Create a Role
1. Navigate to **IAM → Roles → Create role**.
2. Select **Trusted entity type**:
   - **AWS service** → For EC2, Lambda, etc.
   - **Another AWS account** → Cross-account access
   - **Web identity** → For external providers
3. Click **Next: Permissions**.

### Step 2: Attach Policies
- Select an existing policy or custom policy (e.g., `S3FullAccess`).
- Click **Next: Tags** (optional) → Add tags for tracking.
- Click **Next: Review** → Give the role a **name** (e.g., `EC2S3AccessRole`) → **Create role**.

### Step 3: Assign Role to a Service
- For EC2:
  1. Navigate to **EC2 → Instances → Select instance → Actions → Security → Modify IAM role**.
  2. Attach the created role (e.g., `EC2S3AccessRole`).

### Step 4: Test the Role
- Log in to the EC2 instance.
- Try to access S3 using AWS CLI:
```bash
aws s3 ls
```

## 5. Best Practices for Roles
- Assign **least privilege**: only grant required permissions.  
- Use **temporary credentials** for applications.  
- Enable **CloudTrail logging** to monitor role usage.  
- Use **roles for services** instead of embedding access keys in applications.

---

## 6. Learning Outcome
- Understand different **types of IAM roles** and their use cases.  
- Learn to **create, attach, and test roles** in AWS.  
- Implement **secure and temporary access** for users and services.
