# Introduction to Amazon S3

## 1. What is Amazon S3?
- **Amazon Simple Storage Service (S3)** is a scalable, durable, and secure **object storage service** provided by AWS.
- Used to **store and retrieve any amount of data** from anywhere on the web.
- Data is stored as **objects** in **buckets**.

---

## 2. Key Features of S3
- **Scalability**: Automatically scales to store any amount of data.
- **Durability**: Provides **99.999999999% (11 nines)** durability.
- **Availability**: High availability with multiple copies across AWS regions.
- **Security**: Supports encryption (SSE, KMS) and fine-grained access control (IAM, bucket policies).
- **Cost-effective**: Pay only for what you use with different storage classes.

---

## 3. Components of S3
1. **Buckets**: Containers for storing objects. Bucket names are globally unique.
2. **Objects**: Files stored in S3; consist of **data, metadata, and a unique key**.
3. **Keys**: Unique identifier for each object within a bucket.
4. **Regions**: Geographical locations where buckets are created.
5. **Access Control**: Policies, ACLs, and IAM roles define who can access what.

---

## 4. S3 Storage Classes
| Storage Class           | Description                                    | Use Case                                  |
|-------------------------|-----------------------------------------------|------------------------------------------|
| **S3 Standard**         | High durability & availability               | Frequently accessed data                  |
| **S3 Intelligent-Tiering** | Automatic cost optimization                  | Data with unknown or changing access patterns |
| **S3 Standard-IA**      | Infrequently accessed, lower cost            | Backup and disaster recovery             |
| **S3 One Zone-IA**      | Lower-cost, stored in single AZ              | Non-critical, infrequently accessed data |
| **S3 Glacier**          | Archival storage with retrieval time in hours| Long-term backups and archives           |
| **S3 Glacier Deep Archive** | Lowest cost, retrieval within 12 hours       | Rarely accessed data, compliance archives|

---

## 5. Use Cases of S3
- Backup and restore
- Static website hosting
- Data archiving
- Big data analytics
- Disaster recovery
- Storing logs and media files

---

## 6. Advantages of S3
- Fully managed storage
- Highly scalable and durable
- Secure with fine-grained access controls
- Multiple storage classes for cost optimization
- Easy integration with AWS services

  # Creating an S3 Bucket in AWS

## 1. Log in to AWS Management Console
- Go to [AWS Console](https://aws.amazon.com/console/).
- Sign in with a user that has **S3 permissions**.

---

## 2. Navigate to S3
- In the **search bar**, type **S3**.
- Click on **S3** to open the service dashboard.

---

## 3. Create a New Bucket
1. Click **Create bucket**.  
2. **Bucket Name**:
   - Must be **globally unique** across all AWS accounts.
   - Use a meaningful name (e.g., `my-devops-bucket`).  
3. **Region**:
   - Choose the AWS region where you want the bucket to reside.  
4. **Bucket Settings** (optional):
   - Versioning: Enable to keep multiple versions of objects.
   - Encryption: Enable **SSE-S3** or **SSE-KMS** for data security.
   - Public access settings: Block public access unless required.  
5. Click **Create bucket**.

---

## 4. Verify Bucket Creation
- The bucket will appear in your **S3 dashboard**.
- Click on the bucket name to **open and manage objects**.

---

## 5. Best Practices
- Enable **versioning** for critical data.  
- Use **server-side encryption** to secure data at rest.  
- Apply **bucket policies** or **IAM policies** for fine-grained access control.  
- Enable **logging** and **CloudTrail** to monitor bucket access.

---

# Uploading Objects to an S3 Bucket

## 1. Log in to AWS Management Console
- Go to [AWS Console](https://aws.amazon.com/console/).
- Sign in with a user that has **S3 permissions**.

---

## 2. Navigate to S3
- In the **search bar**, type **S3**.
- Click **S3** to open the service dashboard.

---

## 3. Select the Bucket
- From the **bucket list**, click on the bucket where you want to upload objects.

---

## 4. Upload Objects
1. Click **Upload** → **Add files**.
2. Select the **files** from your local system.
3. Optional: **Add folders** if you want to upload multiple files in a directory structure.
4. Click **Next** → **Set permissions**:
   - Default: Keep objects private.
   - Grant public access only if required.  
5. Click **Next** → **Set properties** (optional):
   - Enable **encryption** (SSE-S3 or SSE-KMS).  
   - Set **storage class** (Standard, IA, Glacier, etc.).  
6. Click **Upload**.

---

## 5. Verify Upload
- After upload, the objects appear in the **bucket overview**.
- You can click on the object name to view details, download, or change permissions.

---

## 6. Best Practices
- Use **folders/prefixes** to organize objects.  
- Enable **versioning** to keep track of object changes.  
- Use **server-side encryption** for sensitive data.  
- Apply **bucket policies** or **IAM policies** for controlled access.

---

# Amazon S3 Bucket Properties

## 1. Versioning
- Keeps **multiple versions** of objects in the bucket.
- Helps **recover deleted or overwritten files**.
- Options:
  - **Enabled**
  - **Suspended**

---

## 2. Encryption
- Protects data **at rest**.
- Options:
  - **SSE-S3**: Server-side encryption with S3 managed keys.
  - **SSE-KMS**: Server-side encryption with AWS KMS managed keys.
  - **SSE-C**: Server-side encryption with customer-provided keys.

---

## 3. Logging
- Enable **server access logging** to track requests to the bucket.
- Logs can be stored in another S3 bucket.

---

## 4. Object Lock
- Helps **prevent accidental deletion or modification**.
- Useful for **compliance and regulatory requirements**.
- Options:
  - **Governance mode**: Users with special permissions can override.
  - **Compliance mode**: Cannot be overwritten or deleted.

---

## 5. Tags
- Key-value pairs to **organize, track, and manage costs**.
- Example: `Environment=Production`, `Project=DevOps`.

---

## 6. Events
- Trigger actions on bucket activity:
  - Lambda functions
  - SQS queues
  - SNS topics

---

## 7. Transfer Acceleration
- Speeds up **uploads and downloads** using AWS edge locations.
- Useful for **globally distributed users**.

---

## 8. Storage Class
- Default storage class for new objects:
  - **Standard**
  - **Intelligent-Tiering**
  - **Standard-IA**
  - **One Zone-IA**
  - **Glacier / Deep Archive**

---

## 9. Lifecycle Rules
- Automatically **transition objects to cheaper storage** or **delete them** after a period.
- Helps in **cost optimization** and **data management**.

---

## 10. Permissions
- **Bucket policy**: JSON-based access control.
- **Access Control List (ACL)**: Grant read/write access to specific users.
- **IAM policies**: Control access for users and roles.

---

# S3 Advanced Features

## 1. Versioning
- **Purpose:** Keep multiple versions of an object to protect against accidental deletion or overwrites.  
- **Enable Versioning:**
  1. Go to **S3 → Select Bucket → Properties**.
  2. Click **Versioning → Enable**.
- **Use Cases:**
  - Recover deleted objects.
  - Restore previous object versions.
- **Best Practices:**
  - Enable versioning for **critical data**.
  - Combine with **Lifecycle rules** to manage old versions and reduce costs.

---

## 2. Static Website Hosting
- **Purpose:** Host static websites (HTML, CSS, JS) directly from S3.  
- **Enable Static Website Hosting:**
  1. Go to **S3 → Select Bucket → Properties → Static website hosting**.
  2. Choose **Enable**.
  3. Specify:
     - **Index document** (e.g., `index.html`)
     - **Error document** (optional, e.g., `error.html`)
  4. Save changes.
- **Access Website:**
  - AWS provides a **bucket endpoint URL** to access the site.  
- **Use Cases:**
  - Hosting landing pages, documentation, or static apps.
- **Best Practices:**
  - Enable **CloudFront** for faster delivery and HTTPS support.
  - Keep public access only if required.

---

## 3. Server Access Logging
- **Purpose:** Track requests made to the bucket for **audit and security purposes**.  
- **Enable Server Access Logging:**
  1. Go to **S3 → Select Bucket → Properties → Server access logging**.
  2. Enable logging and select a **target bucket** to store logs.
  3. Save changes.
- **Use Cases:**
  - Monitor who accessed objects and when.
  - Detect unauthorized access.
  - Analyze usage patterns.
- **Best Practices:**
  - Use a **separate bucket** for logs.
  - Apply **lifecycle rules** to manage log retention and reduce storage costs.

  # Amazon S3 Storage Classes

Amazon S3 provides different storage classes to optimize **cost, durability, and access speed** based on your data needs.

---

## 1. S3 Standard
- **Durability & Availability:** 99.999999999% (11 nines) durability, high availability.
- **Use Case:** Frequently accessed data.
- **Features:** Low latency, high throughput.

---

## 2. S3 Intelligent-Tiering
- **Durability & Availability:** Same as Standard.
- **Use Case:** Data with **unknown or changing access patterns**.
- **Features:** Automatically moves objects between **frequent and infrequent access tiers** to save costs.

---

## 3. S3 Standard-IA (Infrequent Access)
- **Durability & Availability:** High durability, lower availability than Standard.
- **Use Case:** Data accessed less frequently but requires rapid access.
- **Cost:** Lower storage cost, charges for retrieval.

---

## 4. S3 One Zone-IA
- **Durability:** Data stored in **single availability zone**.
- **Use Case:** Non-critical, infrequently accessed data.
- **Cost:** Lower than Standard-IA.

---

## 5. S3 Glacier
- **Durability:** 11 nines.
- **Use Case:** Archival storage; data rarely accessed.
- **Retrieval:** Minutes to hours depending on retrieval option.
- **Cost:** Very low storage cost.

---

## 6. S3 Glacier Deep Archive
- **Durability:** 11 nines.
- **Use Case:** Long-term archive, compliance data, rarely accessed.
- **Retrieval:** Within 12 hours.
- **Cost:** Lowest storage cost among all classes.

---

## 7. Summary Table

| Storage Class           | Use Case                              | Retrieval Speed       | Cost         |
|-------------------------|--------------------------------------|--------------------|-------------|
| Standard                | Frequently accessed                  | Milliseconds       | High        |
| Intelligent-Tiering     | Unknown or changing patterns         | Milliseconds       | Optimized   |
| Standard-IA             | Infrequently accessed                 | Milliseconds       | Lower       |
| One Zone-IA             | Infrequently accessed, non-critical  | Milliseconds       | Lower       |
| Glacier                 | Archival, rarely accessed             | Minutes to hours   | Very low    |
| Glacier Deep Archive    | Long-term archive                     | Within 12 hours    | Lowest      |

# Amazon S3 Replication Rules

## 1. What is S3 Replication?
- S3 Replication allows you to **automatically copy objects** from one S3 bucket to another.
- Can be **within the same AWS region (CRR – Cross-Region Replication)** or **across regions (CRR)**.
- Helps with **data redundancy, compliance, and disaster recovery**.

---

## 2. Types of Replication
| Type                          | Description |
|-------------------------------|-------------|
| **Same-Region Replication (SRR)** | Replicates objects within the same AWS region to another bucket. Useful for analytics or compliance. |
| **Cross-Region Replication (CRR)** | Replicates objects to a bucket in another AWS region. Useful for disaster recovery and latency reduction. |

---

## 3. Pre-requisites for Replication
- Source and destination buckets must exist.
- Enable **versioning** on both source and destination buckets.
- Appropriate **IAM role** with permissions to replicate objects.
- Both buckets must have compatible **storage classes**.

---

## 4. Steps to Create a Replication Rule
1. Navigate to **S3 → Select Source Bucket → Management → Replication rules → Create replication rule**.
2. Enter a **rule name**.
3. Choose **scope**:
   - **All objects** or **a subset of objects** using prefix or tags.
4. Select **destination bucket**.
5. Choose **replication options**:
   - Change storage class (optional)
   - Replicate delete markers (optional)
   - Replicate existing objects (optional)
6. Assign or create an **IAM role** for replication.
7. Review and **create the replication rule**.

---

## 5. Best Practices
- Use **Cross-Region Replication** for disaster recovery.
- Enable **replication metrics and notifications** for monitoring.
- Use **prefixes or tags** to replicate only required objects.
- Ensure **versioning** is enabled on both source and destination buckets.
- Monitor **replication status** in the S3 console.

---

## 6. Use Cases
- **Disaster recovery:** Keep a backup copy in another region.
- **Compliance:** Store copies in specific regions to meet regulations.
- **Data locality:** Reduce latency by replicating data closer to users.
- **Analytics:** Copy data to another bucket for analysis without impacting production.

# Amazon S3: Permissions and Metrics

## 1. Permissions Tab

### Purpose:
- Control **who can access the bucket** and what actions they can perform.
- Ensure **data security** and proper access management.

### Key Components:
1. **Block Public Access**
   - Prevents accidental public exposure of data.
   - Can block **all public access** or customize settings.

2. **Access Control List (ACL)**
   - Grant **read/write access** to specific AWS accounts or predefined groups.
   - Less commonly used due to **fine-grained IAM policies**.

3. **Bucket Policy**
   - JSON-based policies that define **permissions at the bucket level**.
   - Example: Allow only specific IAM users to upload objects.

4. **CORS (Cross-Origin Resource Sharing)**
   - Define rules for accessing S3 bucket resources from **other domains** (for web applications).

### Best Practices:
- Always **block public access** unless explicitly needed.
- Use **IAM policies and bucket policies** for fine-grained access.
- Avoid using ACLs unless necessary.

---

## 2. Metrics Tab

### Purpose:
- Provides **insights into bucket usage and performance**.
- Helps in **monitoring and optimizing storage**.

### Key Metrics:
1. **Number of Objects**
   - Total objects in the bucket.
2. **Bucket Size**
   - Total storage used (in bytes or GBs).
3. **Requests**
   - Number of GET, PUT, DELETE requests over time.
4. **Data Transfer**
   - Amount of data transferred in/out of the bucket.
5. **Replication Metrics**
   - Status and success of replication (if enabled).

### Best Practices:
- Enable **CloudWatch metrics** for real-time monitoring.
- Set up **alerts** for unusual activity (e.g., sudden spike in PUT requests).
- Regularly review metrics to **optimize costs and performance**.
